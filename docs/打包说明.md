# 打包与分发说明

本文说明怎么把 CYSC 任务栏打成可分发的包，以及**已经验证到哪一步、哪一步没验证**。

---

## 零、最省事的办法：用 GitHub Actions（推荐）

**不用装任何东西，也不用 Mac** —— 推送到 GitHub 后云端自动构建，
两个平台的包都给你打好，去 Actions 页面下载即可。

```
https://github.com/zhou-yin2025/cysc-taskbar/actions
```

点最新一次 **绿色的 Build** → 页面底部 **Artifacts** 区域：

| Artifact | 内容 | 大小 |
|---|---|---|
| `CYSC-Windows` | `CYSC任务管理-安装程序.exe` + `CYSC-portable.zip` | ~49 MB |
| `CYSC-macOS` | `CYSC.dmg` + `请先读我-macOS.txt` | ~24 MB |

> 下载 Artifacts 需要登录 GitHub 账号（GitHub 的规定，不是本项目的限制）。
> 产物保留 30 天。打 tag（`v*`）时还会自动建 Release 并把两个包挂上去。

**为什么 macOS 也能打**：GitHub 对公开仓库免费提供 macOS 运行器，
等于借一台 Mac 云机器。本项目的开发机是 Windows + MSVC，**无法交叉编译 macOS**
（缺 macOS 版 Qt、SDK、clang、codesign），所以这条路是唯一的选择。

**触发方式**：推送 `main` / 打 tag / 在 Actions 页面手动点 *Run workflow*。

**当前状态：两个平台都通过了**（Windows 12 步、macOS 17 步全绿）。

### 把这条流水线调通踩过的坑（都记着，别再踩）

这段是真实经历：macOS 那一侧连续失败了 **5 次**，每次原因都不同。
GitHub 的 job 日志与 artifact 下载**都要认证**，我一开始拿不到日志只能猜，
**猜错了两次**。后来用 `git credential fill` 从本机 Git Credential Manager
里取出已存的推送凭据去调 API，才拿到日志、看到真因。

| # | 症状 | 真因 |
|---|---|---|
| 1 | macOS「配置与编译」失败 | **`ld: framework 'AGL' not found`** —— Qt 6.8.0 的 macOS CMake 配置会引用 AGL（Apple 已废弃删除的 OpenGL 框架），runner 上是 Xcode 26.6。换 **Qt 6.11.0** 解决 |
| 2 | Windows「安装 Qt 6.11.0」失败 | 6.11.0 的 `win64_msvc2022_64` 包在 Qt 服务器上取不到。**Windows 留在 6.8.0**，两平台版本不同 |
| 3 | 三个测试全 `***Not Run`、`Total Test time = 0.00 sec` | `add_test` 用了**裸目标名**。Windows 上 exe 就在构建目录里所以能找到；macOS 是 app bundle，可执行文件在 `.app/Contents/MacOS/` 下，CTest 找不到。改用 **`$<TARGET_FILE:...>`** |
| 4 | macOS 单元测试挂 4~6 条 | 测试里用了 **`Z:/definitely/not/a/real/drive/x.db`** 这种 Windows 专属路径。在 macOS/Linux 上 `Z:/...` 是**合法的相对路径**，操作会成功，断言就崩。改成「拿一个普通文件当目录用」 |
| 5 | `sips` 转换失败 | **`sips` 不支持 ICO 格式**。改成从 `tools/make_icon.py --icns` 直接产出 `.iconset`（图案源头本来就是这个脚本） |
| 6 | `cp: .../Contents/Resources: No such file or directory` | `MACOSX_BUNDLE_ICON_FILE` 只是往 Info.plist 写个键，**不会创建 Resources 目录**。加 `mkdir -p` |

还有一条**排查纪律**上的教训：中途我在本地跑 Debug 构建得到 590/590 就以为修好了，
其实 Ninja **没重编**受 `test_docstore.h` 影响的 `.obj`（见 README 里那条
「改过公共头文件后必须干净重建」的警告），本地"通过"是假的，CI 一跑就露馅。
**验证必须干净重建。**

下面两条是本地手工打包的办法，想在自己机器上出包时才需要。

## 一、Windows 安装包

### 产物

| 文件 | 大小 | 说明 |
|---|---|---|
| `build/package/CYSC任务管理-安装程序.exe` | 35.6 MB | **单文件安装程序**，双击即装 |
| `build/package/CYSC-portable.zip` | 16.0 MB | 便携版，解压即用 |

安装程序包含：程序本体（已嵌图标）+ 全部 Qt DLL + 平台插件（`qwindows.dll`、`qsqlite.dll`…）+ VC++ 运行库。

### 怎么构建

```bat
scripts\build.bat Release
scripts\package.bat
```

`package.bat` 做 7 件事：查前置条件 → 找 Release exe → 清暂存目录 →
windeployqt 收 Qt 依赖 → 放 VC++ 运行库和图标 → ISCC 编译安装程序 → 顺便打便携版 zip。

### 前置条件

| 需要 | 怎么装 |
|---|---|
| **Inno Setup 6** | `winget install JRSoftware.InnoSetup`（**需要 github.com 可达**，它只从 GitHub 发布） |
| Qt msvc2022_64 | 已有 |
| VC++ 运行库安装包 | 下载 <https://aka.ms/vs/17/release/vc_redist.x64.exe> 放到 `resources/redist/vc_redist.x64.exe` |

### 安装程序行为

- 默认装到 `C:\Program Files\CYSC TaskBar`（可改）
- 建开始菜单快捷方式；**桌面快捷方式**在"附加任务"页可选（默认勾上）
- 如果检测到系统没装 VC++ 运行库，会先静默装一遍（已经装过则跳过）
- 在"应用和功能"里能看到，可正常卸载
- **卸载不清除用户数据**（数据库在 `%LOCALAPPDATA%`）—— 重装不会丢任务

### 关于安装包里的中文

Inno Setup 6 自带 29 种语言但**不含简体中文**（中文是社区维护的 unofficial 包）。
所以 `scripts/ChineseSimplified.isl` 是单独取的，编译时按相对路径引用。

## 二、macOS

### ⚠ 必须先说清楚：本机做不了

这台机器是 Windows + MSVC，**无法交叉编译 macOS 版本**，原因是缺的东西补不上：

| 需要 | 现状 |
|---|---|
| macOS 版 Qt / `macdeployqt` | 只有 `msvc2022_64`、`mingw_64`（都是 Windows 版） |
| 能产出 Mach-O 的编译器 + macOS SDK | 没有 clang、没有 SDK。Windows 上的 MSVC 只出 PE |
| `codesign` / `notarytool` | 苹果专属，不跨平台 |
| Apple 开发者账号 | 需要付费账号 |

而且 **Apple Silicon 的 macOS 默认拒绝未签名未公证的程序**（提示"已损坏"）。
所以即使编出 mac 版，没签名用户也打不开 —— 那不算能交付。

### 在 Mac 上怎么构建

CMakeLists 里已经加好了 macOS 分支（`MACOSX_BUNDLE`、bundle 名/版本/标识符/图标），
所以在 Mac 上不需要改代码。

```bash
# 1) 装 Qt（用官方安装器，选 macOS 版 Qt 6.11 + "Qt Debug Information Files" 可不要）
#    也可以 brew install qt

# 2) 配置 + 构建
cmake -S . -B build/mac -G Ninja \
      -DCMAKE_BUILD_TYPE=Release \
      -DCMAKE_PREFIX_PATH=$HOME/Qt/6.11.0/macos \
      -DCYSC_BUILD_TESTS=ON
cmake --build build/mac

# 3) 跑自检（无界面也要能过）
CYSC_TEST_TMPDIR=$(mktemp -d) ./build/mac/cysc-taskbar.app/Contents/MacOS/cysc-taskbar --guitest

# 4) 图标：.ico 换不出 .icns，要用 iconutil 转
mkdir app.iconset
for s in 16 32 64 128 256 512; do
  sips -z $s $s   resources/app.ico --out app.iconset/icon_${s}x${s}.png
  sips -z $((s*2)) $((s*2)) resources/app.ico --out app.iconset/icon_${s}x${s}@2x.png
done
iconutil -c icns app.iconset -o resources/app.icns
# 然后把 app.icns 放进 bundle：
cp resources/app.icns build/mac/cysc-taskbar.app/Contents/Resources/

# 5) 收 Qt 依赖到 bundle 里
$HOME/Qt/6.11.0/macos/bin/macdeployqt build/mac/cysc-taskbar.app

# 6) 打成 dmg
hdiutil create -volname "CYSC 任务栏" -srcfolder build/mac/cysc-taskbar.app -ov -format UDZO CYSC.dmg
```

**如果不能签名**，至少让用户能手动放行：

```bash
# 用户侧执行一次（或在"系统设置 - 隐私与安全性"里点"仍要打开"）
xattr -cr /Applications/CYSC\ 任务栏.app
```

**如果要正式签名 + 公证**（需要 Apple 开发者账号，$99/年）：

```bash
codesign --deep --force --options runtime \
         --sign "Developer ID Application: <你的名字> (<TEAMID>)" \
         CYSC\ 任务栏.app
xcrun notarytool submit CYSC.dmg --apple-id <账号> --team-id <TEAMID> \
      --password <App 专用密码> --wait
xcrun stapler staple CYSC.dmg
```

### Mac 上要注意的差异

| 项目 | 说明 |
|---|---|
| 无边框窗口 | 代码用的是 `Qt::FramelessWindowHint`，macOS 上行为一致；但标题栏自绘的四个按钮是 Windows 风格，Mac 用户会觉得别扭（可接受，或后续按平台换样式） |
| 托盘图标 | macOS 的菜单栏图标应该用模板图（黑/白单色随系统主题），当前是彩色对勾，在深色菜单栏上可能不协调 |
| 设置存储 | `QSettings` 在 macOS 上写 plist，代码里已经按 `IniFormat` 强制成 INI，位置在 `~/Library/Preferences/` |
| 数据库位置 | macOS 上 `QStandardPaths::AppDataLocation` 指向 `~/Library/Application Support/`，逻辑一致 |

### 遇到过的问题（已解决，记下来免得再犯）

**① 安装报「无法创建目录 …\Temp\is-XXXXX.tmp / 错误 5：拒绝访问」**

排查过程：TEMP 目录 ACL 正常（SYSTEM / Administrators / 当前用户都是 FullControl）、
能手工建目录、**按 Inno 的命名规则建 `is-XXXXX.tmp` 成功 5/5、连报错的那个具体名字
都能建**、模拟提权上下文也能建、Defender 受控文件夹访问是关的、磁盘有 76.9 GB 空余。

**真正的原因是 TEMP 里积压了 31 个陈旧的 `is-*.tmp` 目录**（最早 2025-07-28，
来自以前运行的其它 Inno 安装程序）。清掉之后安装立刻成功。

```powershell
# 清理办法（安全，这些只是安装程序的临时目录）
Get-ChildItem $env:TEMP -Directory | Where-Object { $_.Name -match '^is-' } |
  Remove-Item -Recurse -Force
```

**② `checkedonce` 会记住"不要快捷方式"**

`[Tasks]` 原来写了 `Flags: checkedonce`，意思是 Inno 记住用户上次的选择、下次沿用。
于是只要用户（或静默安装）曾经取消过勾选，**以后每次安装都不再建快捷方式**，
而 `/VERYSILENT` 下又不会弹界面让他改回来。改成默认勾选（flags 留空）。

> 顺带一个**我自己的排查失误**：改完之后我仍然查不到快捷方式，一度以为还有 bug。
> 其实是我查错了地方 —— `PrivilegesRequired=admin` 的安装程序把快捷方式建在
> **所有用户**的菜单里（`C:\ProgramData\...\Start Menu`、`C:\Users\Public\Desktop`），
> 而我查的是当前用户的 `%APPDATA%` 和桌面。**提权安装要看公共位置。**

**③ CMake 里不能让可执行文件名带中文（jom 会链接失败）**

为了让交付的 exe 叫 `CYSC任务管理.exe`，我一开始在 CMakeLists 里设了：

```cmake
set_target_properties(cysc-taskbar PROPERTIES OUTPUT_NAME "CYSC任务管理")
```

Ninja 构建正常，但 **Qt Creator 用的 jom 直接链接失败**：

```
LINK : fatal error LNK1104: 无法打开文件"CYSC?????..exe"
jom: ... [CYSC?????..exe] Error 2
```

原因：**jom 在中文代码页下处理不了非 ASCII 文件名** —— 它传给 `link.exe` 的
`/out:` 参数里文件名已经变成乱码。Ninja 没事，所以这个坑**只在 Qt Creator 那棵树
上暴露**，只跑 `build.bat` 根本发现不了。

**现在的做法**：构建产物保持 ASCII 名 `cysc-taskbar.exe`，
**交付用的中文名在打包阶段改**（`package.bat` 第 4 步复制到暂存目录时重命名）。
这样三棵构建树都不碰非 ASCII 文件名，而用户看到的仍是中文名。

**④ `.bat` 里不能有非 ASCII 字节；`.ps1` / `.iss` 必须带 BOM**

这是同一个"编码"问题的三种表现，README 的「脚本文件的编码规矩」一节有汇总表。
对打包脚本来说最要命的是：`package.bat` 里我曾在注释中写了个中文输出路径，
结果 cmd 把注释行后半段当命令执行，报出 `'se' is not recognized`、
`'found:' is not recognized` 这种完全看不出原因的错。
现在 `package.bat` 里**只有一行**含中文（交付文件名那行），其余全是 ASCII。

### 其它已知事项

| 事项 | 说明 |
|---|---|
| **未签名** | 没有代码签名证书，Windows SmartScreen 会提示"未知发布者"。点"更多信息 → 仍要运行"即可。学生项目正常现象 |
| 安装路径含中文 | 实测把安装包放在中文路径（`D:\...\deepseek workplace\...`）下运行**最初报了那个拒绝访问的错**，但清掉陈旧 tmp 后在中文路径下也能装。为稳妥起见建议放在纯英文路径下运行 |
| 只做 x64 | `ArchitecturesAllowed=x64compatible`，不支持 32 位 Windows |
| 快捷方式位置 | 因为要装到 `Program Files`（需要管理员权限），快捷方式建在**所有用户**的菜单位置。这是提权安装的正常行为 |
